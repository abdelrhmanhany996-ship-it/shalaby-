# تثبيت شلبي من المتصفح (PWA)

`npm run build` ينتج نسخة قابلة للتثبيت داخل `dist` مع Manifest عربي، أيقونات 192 و512 بكسل وأيقونة Maskable وأيقونة Apple بحجم 180 بكسل، وService Worker برقم إصدار مشتق من ملفات البناء. لا توجد مكتبات تشغيل إضافية.

## الاستخدام

- على Chrome وEdge على الكمبيوتر أو Android: اضغط زر «تثبيت التطبيق» أعلى الواجهة أو داخل الإعدادات عند إتاحة التثبيت، أو استخدم خيار التثبيت في قائمة المتصفح. فتح التطبيق المثبت يعرض نافذة مستقلة.
- على iPhone وiPad: افتح الموقع في Safari ← مشاركة ← إضافة إلى الشاشة الرئيسية ← إضافة.
- على إصدارات Safari الداعمة في macOS: ملف ← إضافة إلى Dock.
- عند الفتح في وضع التطبيق المثبت يختفي زر التثبيت. التثبيت متاح لكل منصب ولا يضيف أي صلاحيات.
- زر التثبيت لا يفتح طلبًا تلقائيًا؛ المستخدم يبدأه بنفسه. عند عدم وجود طلب متصفح جاهز، تظهر تعليمات الطريقة المتاحة.

## الاتصال والتحديثات

الخاصية للتثبيت وليست وضع تشغيل CRM دون إنترنت. يحتفظ الـService Worker فقط بملفات الواجهة العامة (JS وCSS والخطوط والأيقونات) وصفحة اتصال بسيطة، بقائمة ملفات محددة أثناء البناء. لا يخزن HTML التطبيق الرئيسي أو استجابات API أو طلبات Firebase أو بيانات العملاء أو الصلاحيات في Cache Storage. بيانات localStorage الموجودة في الـPrototype لم يتغير تخزينها بهذه الخاصية.

فتح التطبيق يستعلم عن الصفحة من الشبكة. عند انقطاع الاتصال تظهر صفحة «محتاجين اتصال بالإنترنت» مع إعادة المحاولة، دون عرض ملفات عملاء قديمة. عند رجوع الاتصال يستطيع المستخدم فتح التطبيق مجددًا.

نسخة الـService Worker الجديدة تنتظر. تظهر رسالة «نسخة جديدة متاحة. احفظ شغلك قبل التحديث» مع «تحديث الآن» و«لاحقًا». لا يحدث تحديث إجباري أو إعادة تحميل أثناء ملء نموذج. يُعاد تحميل التبويب الذي طلب التحديث فقط؛ التبويبات الأخرى لا تعيد التحميل تلقائيًا. تُحذف فقط إصدارات الكاش السابقة الخاصة بشلبي.

## النشر على test.engsaber.space

1. ابنِ المشروع وارفع **كل محتويات** `dist` إلى جذر الـsubdomain، بما فيها الملفات المخفية مثل `.htaccess`، والمجلدات `assets` و`fonts` و`icons`.
2. فعّل HTTPS بشهادة صالحة. التثبيت وService Worker يعملان على HTTPS أو localhost للاختبار، ولا يعملان على عنوان HTTP عادي.
3. يجب أن يرجع `/manifest.webmanifest` و`/sw.js` ملفاتها الحقيقية برمز 200، وألا تعيد قاعدة توجيه عامة ملف `index.html` مكانها.
4. إعداد `.htaccess` المرفق يضبط MIME للـManifest ويطلب إعادة فحص ملفات الصفحة والـManifest والـService Worker في Apache/LiteSpeed. إذا كان هناك CDN أو إعداد كاش في لوحة الاستضافة، لا تفرض عليه كاش طويلًا لهذه الملفات. أسماء JS/CSS الناتجة تحتوي hash ويمكن تخزينها مدة أطول.
5. النسخة الحالية مُعدة لجذر الـsubdomain `/`. اختبر البناء عبر `npm run preview -- --host 0.0.0.0`؛ خادم التطوير/HMR لا يسجل Service Worker.

إضافة PWA لا تنشر الموقع على Hostinger ولا توفر حسابات دخول أو مزامنة مركزية؛ متطلبات صلاحيات الإنتاج موثقة في `roles-and-permissions.md`.

## التحقق

- `npm run lint` و`npm test` و`npm run build`.
- اختبارات `tests/pwa.test.ts` تتحقق من سياسة الكاش، التنقل المتصل وغير المتصل، استثناء طلبات البيانات، تنظيف الكاش وتفعيل التحديث باختيار المستخدم.
- فحص المتصفح لنسخة الإنتاج: Manifest وأبعاد الأيقونات ومعايير تثبيت Chromium، تسجيل Service Worker، التثبيت وحالة التطبيق المثبت، انقطاع الاتصال والعودة، وتحديث حقيقي ينتظر موافقة المستخدم. طلب التثبيت نفسه يُختبر بحدث متصفح محاكى؛ لم يُثبت التطبيق فعليًا على هاتف أو جهاز مستخدم.
