# مناصب شلبي وصلاحيات النسخة التجريبية

هذه المراجعة تربط بيانات الواجهة والشاشات والإجراءات بمصفوفة واحدة بدل فحوص أدوار متفرقة داخل الصفحات.

| المنصب | النطاق الافتراضي | العمل الأساسي |
|---|---|---|
| مدير عام المؤسسة | جميع الفروع | أداء الفروع والأقسام، الموظفون والهيكل والرواتب وسجل العمليات وإدارة المصفوفة |
| مشرف عام | الفروع المحددة في ملفه؛ جميع الفروع عند عدم تحديد فروع | مراقبة الأداء، توزيع العملاء، إدارة الموظفين الأقل صلاحية والفرق |
| مشرف مختص | الفروع المحددة في ملفه، أو فرعه المسجل؛ لا بيانات إذا لم يحدد أي نطاق | حسب اختصاص الحسابات أو المبيعات أو تشغيل الفروع |
| مدير فرع | فرعه فقط | متابعة أداء فريقه وتوزيع العملاء وإدارة موظفي الفرع وتسجيل العمليات |
| موظف بفرع | سجلاته وتكليفاته داخل فرعه | العملاء والزيارات والمتابعات والتعاقدات والفواتير المرتبطة بعمله |

المسمى الوظيفي مستقل عن المنصب: يمكن تسمية موظف بفرع «سيلز» أو غير ذلك من دليل المسميات. المسمى وحده لا يمنح صلاحيات إضافية. الملفات القديمة تُقرأ بنفس معرّفاتها؛ المدير العام القديم يُوحّد مع مدير عام المؤسسة، وقائد الفريق القديم يصبح موظف بفرع مع الاحتفاظ بمسمّاه.

المشرف المختص له ثلاثة قوالب أولية داخل المصفوفة: الحسابات، المبيعات، وتشغيل الفروع. يختار المدير العام الاختصاص والفروع من ملف الموظف. تغيير المصفوفة يؤثر في كل الموظفين الذين يستخدمون القالب نفسه. صلاحية عرض البيانات شرط للإجراءات المرتبطة بها، وتفعّل واجهة المصفوفة المتطلبات أو تلغي الإجراءات التابعة عند إلغاء العرض.

إدارة المصفوفة متاحة لمدير عام المؤسسة فقط ولا يمكن تفويضها بتحديد مربع آخر. المسار: الرئيسية ← مصفوفة الصلاحيات، أو إدارة المؤسسة ← مصفوفة الصلاحيات. لا تضاف هذه الصلاحية للمشرف العام أو مدير الفرع عبر أي نموذج موظف.

## سلوك تمت مراجعته

- الرئيسية تعرض رقابة الفروع والمسؤول عن التأخير للإدارة، وتعرض المهام الشخصية للموظف. المقارنة مختصرة مع عرض كل الفروع عند الطلب. عدم وجود سجلات لا يعتبر دليل تقصير.
- العملاء والبحث والتصدير والمتابعات والزيارات والتعاقدات والفواتير والموظفون والفرق والتفاصيل الفرعية تعتمد البيانات المسموح بها داخل نطاق العمل.
- الاتصال وواتساب وطلب التقييم يحتاجون صلاحية التواصل وعميلًا أو مهمة مسندة للشخص نفسه. المدير العام لا تظهر له أزرار تشغيل المبيعات افتراضيًا.
- إتمام المتابعة للمسؤول عنها فقط، ولا يعاد إتمام مهمة مكتملة. نقل عميل ينقل متابعاته المعلّقة إلى المسؤول الجديد، مع الاحتفاظ بالتاريخ المنجز.
- مشرف الحسابات يستخدم بيانات العميل الأساسية اللازمة للفاتورة فقط، ولا يحصل على ملاحظات العملاء أو شاشات التواصل.
- مدير الفرع لا يستطيع ترقية شخص لمنصب أعلى منه أو تعديل صلاحيات أو اختصاصات أو فروع الإشراف. الرواتب متاحة للمدير العام افتراضيًا.
- إنشاء فرع يتطلب الشركة والمحافظة، وإنشاء مخزن يسمح باختيار المحافظة والفرع المرتبط والسعة بدل قيم ثابتة. دليل الموظفين يعكس الفرع والمسميات المختارة.
- تغيير هوية المعاينة أو صلاحيات المستخدم يغلق حالة الشاشة السابقة، بما فيها البحث والنماذج والملفات المفتوحة.
- الإعدادات الشخصية لا تعرض التوزيع الآلي غير المنفذ أو تصفير البيانات لغير المدير العام. إضافة التصنيفات والوسطاء تخضع لصلاحياتها حتى داخل النماذج الفرعية.

## التحقق

`npm test` يشغّل اختبارات فصل البيانات، تجاوز الصلاحيات، اختصاص المشرف، تعديل المصفوفة، الإسناد، ومنع الحالات غير الصحيحة. `npm run lint` يفحص TypeScript، و`npm run build` يبني النسخة.

تمت مراجعة المتصفح على الكمبيوتر والموبايل، بما يشمل المناصب الخمسة واختصاصات المشرف الثلاثة، جميع الشاشات المتاحة لكل قالب، حفظ الصلاحيات وإعادة التحميل، إنشاء عميل ومتابعته وإتمام المهمة، وإصدار فاتورة بواسطة مشرف الحسابات. حُظرت الاتصالات الخارجية أثناء الاختبارات حتى لا تكتب بيانات اختبار في Firebase الفعلي.

## حدود النسخة الحالية

المصفوفة وبيانات الموظفين محفوظة في localStorage في هذا المتصفح. فحوص الواجهة تمنع إجراءات غير مناسبة أثناء الاستخدام المعتاد؛ ليست آلية تفويض آمنة على الخادم. تسجيل الدخول الحقيقي، ربط الهوية بملف الموظف، تخزين المصفوفة مركزيًا، وتطبيق النطاق والصلاحيات في الخادم أو قواعد قاعدة البيانات لازمة قبل الاستخدام الفعلي عبر أجهزة الفروع. ملف `firestore.rules` الحالي يحتوي سماحًا عامًا لبعض المجموعات؛ لم تُنشر أو تُغيّر قواعد قاعدة البيانات ضمن هذه المراجعة، ولا يمكن الجزم بالقواعد المنشورة عن بُعد.
